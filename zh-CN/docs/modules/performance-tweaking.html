性能调优

如果您运行的是大型服务器网络，则可以调整 QuickShop-Hikari 设置以获得更好的性能。

info

QuickShop-Hikari 的默认配置注重性能和玩家体验平衡。 无需调整，除非插件影响了服务器性能。

修剪孤立的数据​

随着 QuickShop-Hikari 的操作，一些记录可能会被隔离，不再被其他数据引用。

修剪孤立的数据可以改善插件启动时间和数据库查询时间。

/quickshop database trim

清除历史记录日志​

caution

清除历史日志还将重置此服务器上的所有QuickShop-Hikari统计，并有可能使依赖内部统计的其他插件停止工作。

谨慎操作，注意备份！

QuickShop-Hikari会将日志记录到数据库中，包括：

  • 系统日志
  • 商店创建
  • 商店更改
  • 商店删除
  • 玩家购买
  • QuickShop-Hikari的任何交易

你可以输入如下命令清理：

/quickshop database purgelogs

使用虚拟展示物品​

note

默认情况下，此功能 已启用 ，但仅在安装了 ProtocolLib 或 PacketEvents 时才有效。

如果你还没试过虚拟展示物品，现在就试试看吧！ 它能极大提升悬浮物的性能和服务器的刻时间计算。

请参阅 悬浮物系统

关闭离线玩家自动补全功能​

note

默认情况下，此功能 禁用 。

离线玩家名补全可以优化使用体验。
若使用离线模式，这会创建大量的 Mojang API 访问请求。
这会增加 Mojang API 服务器的负载，可能会在过多请求后临时封禁你的的 IP 几分钟。
更改 config.yml 中的以下设置，可以禁用这个功能：

# 是否允许 QS 使用离线玩家列表填入 tab 补全列表？
# 可以提升玩家使用体验，但也可能在请求数量过大时导致服务器卡顿。
# false = 只使用在线玩家列表。
# true = 列出所有加入过服务器的玩家列表。
include-offlineplayer-list: false

关闭响应式剩余库存/剩余空间重计算​

note

默认情况下，此功能 禁用 。

QuickShop-Hikari会在漏斗等物品传输事件上，重新计算商店库存内容。
它可能会在繁忙或生电服务器上造成相当高的负载，并降低服务器 TPS。

可以通过更改下面的设置禁用它：

shop:
  # 当某些内容（例如漏斗）触发 InventoryMoveItemEvent 改变容器内容时是否更新告示牌？
  # 若影响了服务器性能，请将其禁用。
  update-sign-when-inventory-moving: false

关闭展示物品自动取消显示​

note

默认情况下，此功能 禁用 。

展示物自动删除功能会检查附近所有载入的商店位置，计算同一世界所有在线玩家与其的距离。
这可能会对服务器造成严重负担。

通过更改下面的设置禁用此功能：

shop:
  # 允许 QuickShop 在商店范围内没有玩家时自动禁用物品展示。
  display-auto-despawn: false

禁用 QuickShop-Remake 商店信息牌迁移​

note

默认情况下，此功能 禁用 。

如果您的服务器没有从 QuickShop-Reemake 迁移，您应该关闭此选项，以避免不必要的告示牌元数据检查。

# 旧数据更新器
# 打开后会让 QuickShop 执行额外检查并可能影响性能。
# 若你是从旧版本更新，则建议将其开启。
legacy-updater:
  shop-sign: false
